Draw the same mesh with less garbage.

Inference is only part of the frame. Your visualization path currently creates thousands of short-lived JavaScript objects before Canvas draws anything.

Why this matters. MediaPipe's Web detectForVideo() call blocks the main thread. Face Mesh then smooths 478 landmarks and traces thousands of edges on that same thread, so allocation and garbage collection can become visible as uneven frames.

What the audit found

  • The vendored MediaPipe bundle defines 2,556 tessellation connections. Full Mesh is on by default, and all 2,556 are traced every detected frame (lines 795–802).
  • traceConnections() calls getConnectionEndpoints() once and projectLandmark() twice per edge (lines 738–750). For tessellation alone, that creates at least 7,668 temporary objects per face per frame.
  • Feature, oval, and iris groups add another 132 traced connections after the tessellation.
  • smoothFaceLandmarks() scans all 478 landmarks for motion, then maps them into 478 new objects every frame (lines 819–852).
  • The inference canvas uses the full displayed canvas size multiplied by device pixel ratio (lines 610–620), and it is copied into the visible canvas every frame (lines 1258–1269).
  • syncCanvasSize() reads layout from inside the hot loop (line 1251), despite having actual resize handlers.
  • The optional label filter sets a 600 × devicePixelRatio pixel font (line 1232), which is almost certainly a defect and should be handled separately.
  • The June 16 face record was 11 render FPS, 15–16 ms inference, and 10 IPS. That is historical context, not today's baseline.
Required change: remove temporary point objects from mesh tracing. Read each connection's verified start/end indices and write scalar canvas coordinates directly into the path. Preserve the exact connection groups, composite mode, widths, colors, glow, and Full Mesh default. Do not improve the number by drawing less.

Do not touch these knobs

Keep the model, model outputs, input size, delegate, camera constraints, smoothing, and mesh detail unchanged. This experiment isolates JavaScript allocation in the drawing path.

Protocol

  1. Start python3 -m http.server 5174 from the repo root and open http://localhost:5174/mediapipe-lab/sims/face-mesh/.
  2. Fill in plan.md before code changes.
  3. Keep Full Mesh on. Warm up for 10 seconds, then record five 10-second runs in results.md.
  4. Record a Chrome Performance trace long enough to include several seconds of steady tracking. Note garbage-collection events; do not guess at them.
  5. Remove the hot-loop objects, repeat five runs, and compare traces and screenshots.

Backlog found—not today's change

  • Move canvas sizing out of the frame loop after profiling.

  • Pause camera work explicitly while the document is hidden.
